Scope: does the documentation describe the application that exists. Read-only audit against the working tree as of 2026-09-20 (includes uncommitted changes: `backend/app/backfill_category.py`, edits to `Charts.tsx`/`use-analytics.ts`/`test_fixi_ui_support.py`). `pytest tests/ -q` re-run for this audit: **154 passed**.

## 3. docs/18_FRONTEND_UX.md — no banner, describes a retired UI

This document specifies the **old `frontend/`** app (React Flow work graph, a "Communication drawer," a "Research drawer," a "Demo controls" region) and does not describe `frontend-fixi`, which is what actually ships (`main.py` serves `frontend-fixi/dist`).

- **Research drawer** (required region): never built anywhere — confirmed, no `research`/`Tavily` string in any `frontend-fixi` component beyond directory-form trade options and a documents-panel unrelated match.
- **Demo controls region**: correctly obsolete — `app/api/demo.py` and the "Play demo"/"Simulate an observation" controls were deliberately removed (docs/26 #22). The doc still lists this as a *required* region.
- **Polling spec** (*"every second during active work, five seconds while idle"*): not implemented as specified. Actual intervals are fixed per hook, never active/idle-adaptive: `use-case-detail.ts` 2000ms, `use-case-events/list/messages.ts` 4000ms, `use-dashboard-metrics`/`use-notifications`/`use-upcoming-appointments` 5000ms, `use-agent-status`/`use-property-history` 10000ms.
- **Provenance badges** (*"Show distinct provenance badges per event/effect... A case can mix live voice, live Gemini and simulated booking"*): partially implemented. `Pill` provenance badges exist for communications and contractor-report evidence (`maintenance.tickets.$ticketId...tsx:346,701`, `DocumentsPanel.tsx:142`), but **`WorkGraph.tsx` and `CaseProgress.tsx` — the two components showing appointment/booking status — render no provenance label at all**, grepped and confirmed empty. Since every appointment in this app is booked through `MockBookingConnector` (always SIMULATED), this is exactly the component that most needs the badge and doesn't have one.
- **Voice evidence states** (connected/listening/speaking, "Transcript processing," "Recording pending"): not applicable — there is no voice panel in `frontend-fixi` at all (confirmed, see README audit below), so none of this UI exists to check against.

**Recommendation for the banner**: docs/18 should carry the same "Partially superseded" framing as 16/17 is not strong enough here — the *primary screen concept itself* (three-node graph + drawers) was abandoned for a full multi-destination app. Banner should say: *"Superseded (2026-09-20). This document describes the retired single-case hackathon screen, not `frontend-fixi`'s multi-destination UI. See docs/UI2_IMPLEMENTATION_HANDOFF.md and docs/UI2_INTERACTION_CHECKLIST.md for the current UI contract. The Research drawer this document requires was never built in either UI."*

## 6. UI2_* docs — audited for overstatement

These four documents are, on the whole, unusually careful about hedging ("type" vs "manual" verification levels, explicit "not clicked through" lists, "open by design" vs "fixed"). The adversarial pass below is what actually held up:

- **UI2_IMPLEMENTATION_HANDOFF.md §4, "the two genuine LIVE ElevenLabs communications are intact"** (about the migrated-copy rehearsal) — technically true (the rows survived the migration unmodified) but reads as an endorsement of data quality. As shown in §1 above, those two rows have an **empty transcript** and a **failed recording fetch**. "Intact" here means "not corrupted by the migration," not "contain real evidence." A reader skimming this line would reasonably conclude the live ElevenLabs gate has real supporting data somewhere in this database; it does not.
- **docs/26 entry 20 / README's "Wiring a specific live agent was explicitly descoped by product decision"** — frames non-completion of the ElevenLabs gate as a pure scope decision. The DB evidence (`error_code: "details_fetch_failed: [Errno 11001] getaddrinfo failed"`, a DNS resolution failure) shows an actual live session-creation attempt was made against the real ElevenLabs API (real `conv_...` IDs were returned) and then failed on network access, not merely "not attempted." Both things can be true (the *decision* not to pursue further configuration, and a *separate* failed low-level attempt), but the docs only tell the first half of the story. This is the report's most understated discrepancy, not because it's dishonest, but because it's incomplete in a way that makes the gap look more deliberate/controlled than the evidence shows.
- **UI2_TODO.md items #1 (donut) and #2 (backfill) are both still marked `TODO`**, but the working tree already contains a full, matching implementation for both (`backend/app/backfill_category.py`, 172 lines, uncommitted; `Charts.tsx`/`use-analytics.ts` diffs implementing exactly the "Uncategorised" behavior the TODO describes) plus a new 98-line test file. This is understatement, not overstatement — the doc is stale in the safe direction — but it's still doc-vs-reality drift worth a status update before anyone re-reads the TODO queue.
- No other overstated "done"/"verified" claim in the four UI2 docs survived a check: the "Not clicked through" and "Inherited, still open" sections in the handoff/checklist are consistent with what the code actually shows (verified the ESCALATED-continues-executing claim above, for example — it is real, not overstated).

## Summary

- **CLAUDE.md rules violated**: 1 clear (`MockBookingConnector` invents availability — the given worked example, confirmed). 2 additional rules that hold in code but do not hold in the one real dataset that exercises them (fake-live-trace risk on 2 LIVE-labelled-but-empty communications; the ElevenLabs recording/transcript guarantee, never actually satisfied end to end).
- **Misleading docs**: 4 — docs/18 (describes an abandoned UI, no banner), docs/04 and docs/20 (describe a retired product, no banner, sit first in CLAUDE.md's own reading order), and README.md (one wrong port, one false "gap" claim about `DecisionCard`/`WorkGraph`). docs/16's banner is insufficient for the two deleted `/demo/*` routes it still lists as current.
- **Single worst discrepancy**: the two `provenance=LIVE` communications in `backend/data/repairflow.db` have an empty transcript and a failed recording fetch (`getaddrinfo failed`), while the project's own documentation (README, docs/26 #20, UI2 handoff) describes the ElevenLabs gap purely as an undone *decision* ("explicitly descoped," "not attempted") rather than disclosing that a live call **was** attempted and failed on network access. CLAUDE.md requires persisted, correlated, displayed, playable audio and full transcript for exactly this case — the code can do it, but on the one dataset that matters, it has never actually happened.
