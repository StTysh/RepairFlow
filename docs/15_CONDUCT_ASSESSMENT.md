# 15 — Conduct assessment

**Decision: no Conduct integration in MVP.**

The event links Conduct as a co-host. Its official site describes an AI operating system for enterprise software, including understanding existing systems and supporting changes/migrations in environments such as SAP. That does not establish a relevant property-maintenance API. [Conduct](https://conduct.ai), [Event page](https://luma.com/ldn-hack).

| Question | Finding |
|---|---|
| What does Conduct provide publicly? | Enterprise-software understanding and change/migration capabilities, as described by the company |
| Public maintenance/dispatch API? | Not established in reviewed official material |
| Hackathon-specific API/product? | UNKNOWN |
| Credits? | Event promises unspecified provider credits; allocation to a specific Conduct product is UNKNOWN |
| Mandatory? | No published requirement found; absence of a published rule is not organizer confirmation |
| Prize incentive? | UNKNOWN |
| Useful responsibility in this design? | None justified for an empty-repository Python maintenance prototype |

If organizers offer a concrete tool on the day, evaluate its documented API, setup time and direct contribution to the demo before changing the architecture. A future integration might help with legacy enterprise-system understanding, but that is an inference, not a documented integration or MVP requirement.

Do not invent a Conduct SDK, endpoint, credit value or partnership benefit. Removing Conduct has no effect on the selected runtime. Co-host status is acknowledged without decorative integration.
